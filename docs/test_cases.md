## 案例 A：日本高精度编码器出口审查收紧

**复现方式**：事件 EVT-01 → `shocks_from_events` 自动转为 DEP-01 冲击参数
（新交期 = 正常 8 周 + 12 周 = 20 周，供应削减 0%）。

**预期**：能推演出断供时间点，并给出受影响订单清单与影响金额，供决策者评估应对方案。

**实测**：

| 项目 | 实测值 |
| --- | --- |
| 转出的推演参数 | 供应削减 0%；新交期 20 周 |
| 断供周次 | 第 17 周 |
| 受影响订单数 | 0 |
| 受影响金额（万元） | 0 |
| 订单状态 | 3 个订单（due 8/12/16 周）均在断供前可交付 |

**结论（已定口径）**：断供点推演可用；现有 3 个订单交付期都早于第 17 周，
因此“受影响订单”为空是符合赛题设定的结果。案例重点定为“断供点预警 + 第 17 周后
新增订单无库存支撑提示 + 应对方案比较”，不改动三批订单的种子数据。

## 案例 C：工业控制芯片上游信息缺失

**预期**：系统明确标注 DEP-02 上游生产与授权关系不明，量化“信息可见性”风险，
不编造上游事实，并给出补全路径（索取授权链 / 人工尽调）。

**实测**：

| 行为 | 当前状态 |
| --- | --- |
| 上游是否已知 | DEP-02 = 否（`upstream_known=0`） |
| 信息可见性风险 | 100 分（满格） |
| 暴露度影响 | DEP-02 综合 71.5，最高风险，主要受可见性/集中度/事件共同推动 |
| 图谱表达 | 依赖图画为红色虚线（上游不明） |
| 明确“高不确定性”提示 | 缺少面向用户的结论级提示 |
| 补全路径/行动建议 | 仅存在于种子数据备注，未在报告与 UI 中结构化输出 |

**结论（已实现）**：风险量化和图谱标注原本已具备；里程碑 4 新增：
暴露度报告输出“主要风险因子”与“不确定性提示”（含授权链/人工尽调建议和
待核实事件提醒），并在 UI 案例页结构化展示。

## 案例 D：媒体报道置信度不足 / 相互矛盾

**预期**：系统不把低置信度或传闻当作确定事实，条目保持“待核实”并展示来源，
提示人工介入；冲突报道不产生确定结论。

**实测**：

| 行为 | 当前状态 |
| --- | --- |
| EVT-03 入库标注 | verify + low confidence + rumor（✅） |
| 暴露度计算 | 只统计 active 事件，EVT-03 不计入事件强度（✅ 保守） |
| 事件库展示 | 进入“待核实”列表（✅） |
| 冲突报道建模 | 无“同一议题多来源相互矛盾”的数据结构或比较逻辑（缺少） |
| 情景推演入口 | UI 允许勾选“（待核实）”事件直接推演，且无显著风险提示（需处理） |

**结论（已实现）**：保守入库与不参与评分的行为正确；里程碑 4 进一步实现：
`shocks_from_events` 默认忽略 verify 事件；UI 勾选待核实事件时自动忽略并提示；
仅 `include_pending=True` 时作为“假设分析”显式启用。冲突来源比较留作已知局限。
