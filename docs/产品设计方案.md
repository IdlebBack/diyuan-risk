# 赛道 B 产品设计方案：地缘风险（供应链地缘风险雷达）

> 依据《"AI+地缘政治风险高校挑战赛"活动指南》赛道 B 要求编写
> 方向来源：附录二·参考方向三（全球供应链与产业安全）

---

## 一、产品定位

**一句话**：面向高端智能装备制造企业的"供应链地缘风险雷达"——帮助采购与供应链管理者识别关键依赖、感知地缘风险信号、量化暴露程度，并推演不同风险情景下的断供影响与应对方案。

**赛道对应**：地缘政治风险分析中的"行动推演（Simulating Decisions）"能力，聚焦附录一风险框架中"供应链生态网络的因果级联传导不确定性"。

**产品形态**：可本地运行、可在线部署的 Web 应用（AI 智能体 + 知识图谱 + 情景模拟器）。

## 二、目标用户与使用场景

| 用户 | 使用场景 | 任务 |
| --- | --- | --- |
| 采购/供应链管理者 | 维护供应商清单、评估关键零部件依赖 | 识别哪些供应关系最易受地缘事件冲击 |
| 生产管理者 | 面对交期延长/断供风险安排生产 | 判断库存能撑多久、哪些订单会延误 |
| 企业战略部门 | 跟踪出口管制、贸易政策变化 | 感知外部信号，提前调整备货与供应商策略 |

**主场景（以指南模拟企业 XX 智能装备为例）**：公司关键零部件依赖日本编码器（40% 伺服系统）、新加坡经销的工业控制芯片（65% 某型号，上游授权关系不明）、德国工业相机；近期多国出口审查收紧，部分供应商交期由 8 周拉长至 16–20 周；关键零部件安全库存约 12 周，未来四个月有 3 批国内外订单需交付。

## 三、核心痛点

1. **依赖关系不透明**：只知道直接供应商，看不清上游二级供应商与授权关系，无法判断真正的断供风险点。
2. **部门数据割裂**：采购掌握供应商与库存、战略掌握国际政策、销售掌握交付要求，信息没有打通。
3. **信号分散**：出口管制、航运中断、地缘冲突等信号散落在新闻、政策文件、行业报告中，人工跟踪成本高、容易漏。
4. **无法量化暴露度**：说不清"哪个环节最危险、危险到什么程度"。
5. **难以比较应对方案**：加库存、调生产顺序、找替代供应商、与客户协商交期，各有代价，缺少统一比较工具。
6. **缺乏"如果发生 X"的推演能力**：风险事件到实际断供/延误之间的传导链条只能靠经验拍脑袋。

## 四、核心功能（MVP）

### 功能 1：供应链依赖建模
- 维护 BOM/供应商清单（组件、供应商、国家/地区、采购占比、库存、交期、可替代性、认证周期）。
- 自动构建多级依赖图谱（直接供应商 + 可标注的上游/授权关系），计算**依赖集中度**（单一供应商/单一国家占比）。

### 功能 2：地缘风险信号雷达
- 定时/手动抓取目标国家、目标零部件的政策文件、新闻、出口管制清单动态。
- AI 抽取风险事件（主体、国家、时间、措施、影响对象、来源链接），区分**事实 / 推断 / 待核实**。
- 事件与依赖图谱中的节点关联，命中时在风险看板置顶提示。

### 功能 3：暴露度评估
- 对每个组件/供应商计算**地缘暴露度（五因子加权）= 依赖集中度 20% + 事件强度 25%（叠加公式）
  + 可替代性风险 20% + 库存缓冲风险 15% + 信息可见性风险 20%**。
- 输出可解释的分数与排名（Top 暴露清单），分数构成逐项展示，而非黑盒。
- 配套权重敏感性分析与反事实案例校验，确保结论对参数不敏感。

### 功能 4：情景推演器
- 用户设定事件参数（如"日本对华编码器出口管制，交期 20 周、供应量下降 30%"）。
- 计入**在途订单**与持续补货，支持在途损失/延误参数；推演库存消耗曲线、断供时间点、
  受影响订单清单与影响金额。
- 支持**多事件叠加**（同依赖自动合并）与多情景对比（基准 / 悲观 / 乐观）。

### 功能 5：应对方案比较
- 预置四类方案：增加安全库存、调整生产顺序、启动替代供应商认证、与客户协商交期。
- 对每类方案给出成本/时间/效果估算、风险与不确定性标注、实施建议。
- 所有 AI 输出必须附**来源与置信度**，重大判断提示"需专业人员/采购确认"。

### 功能 6：边界与置信度提示（评审点）
- 信息缺失（如二级供应商未知）时明确标注并给出补全路径。
- 报道矛盾或置信度不足时，系统主动降级结论、请求人工介入。
- 内置 1–2 个边界案例演示（见"验证与演示"）。

## 五、技术方案

| 模块 | 选型 | 说明 |
| --- | --- | --- |
| 应用框架 | Streamlit（快速可演示）或 FastAPI + 轻前端 | 优先 Streamlit 保证 10 月中旬前可跑通 |
| 数据存储 | SQLite + CSV 种子数据 | 模拟企业数据 + 公开数据 |
| 依赖图谱 | NetworkX + Pyvis/ECharts 可视化 | 图谱交互展示 |
| 事件抽取 | LLM API + 结构化输出 | 新闻/政策文本 → JSON 风险事件 |
| 推演引擎 | Python 库存/交期离散模型 | 确定性 + 简单概率两种模式 |
| 前端可视化 | ECharts（趋势、排名、桑基/关系图） | 数据看板 |

**数据来源（公开）**：出口管制清单（美国 BIS、日本经产省、欧盟）、海关/贸易数据、新闻 RSS、行业报告；模拟企业数据直接取自指南附录二。

**AI 使用原则**：AI 承担"文本结构化抽取、事件摘要、方案推理、证据链接"等关键任务，但所有关键结论必须可溯源、可解释、标注置信度——正好回应评审点"AI 是否合理使用"与"能否说明数据与生成内容的边界"。

## 六、验证与演示（真实/模拟案例）

1. **案例 A（基准）**：日本高精度编码器出口审查收紧 → 交期 20 周、库存 12 周 → 推演断供时间点与受影响订单。
2. **案例 B（传导）**：红海/关键海峡航运中断 → 新加坡经销芯片到货延迟 → 生产排期连锁影响。
3. **边界案例 C（信息缺失）**：工业控制芯片上游生产与授权关系未知 → 系统标注"高不确定性"，建议向经销商索取上游授权链或人工尽调。
4. **边界案例 D（置信度不足）**：媒体报道互相矛盾 → 系统不给出确定结论，标注冲突来源并提示人工核实。
